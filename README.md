# 筋トレ記録 - YUU Edition

公開先: https://yuuuh26.github.io/workout/

## 更新後の初回操作

1. ほかのタブや以前のアプリ画面を閉じ、上記URLをいつものChromeで開き直す。
2. 画面下部の「① 移行前バックアップを保存」でJSONを保存し、ダウンロード先にファイルがあることを確認する。
3. 「② 保存したので移行する」を押す。件数・全項目を読み直して照合後、IndexedDBへ切り替わる。
4. 履歴と件数を確認する。旧localStorageは自動削除しない。

記録は先に端末へ保存します。クラウド版では接続後Cloudflareへ自動バックアップします。本人の記録や復旧キーはGitHubへ送信しません。
移行前にバックアップ後の記録変更があると、バックアップを取り直します。
移行後の読み込みエラーでは旧データへ自動的に戻しません。再読み込みしてください。

## 機能

- 種目・回数・自動日時、種目追加・削除、履歴削除、自己ベスト、期間表示
- 折りたたみから過去日時指定。保存成功後に現在日時へリセット
- 従来のクリップボード出力と全件Markdown出力
- Markdown名: `筋トレ記録_YYYYMMDD-YYYYMMDD.md`（収録日時の最小〜最大）
- JSONバックアップ・復元（確認後に置換。置換前JSONもダウンロード）
- 永続ストレージ申請・状態表示（拒否でも利用可能）
- 添付の健康・成長モチーフを192/512pxのアイコンとして使用
- noindex, nofollow（アクセス制限ではありません）

IndexedDB名: `yuu-workout-v1`。旧キー: `pureLocalHistory`, `pureLocalMenus`。
記録の日時・ID・未知の項目もJSON/移行では保持。重複IDの記録も統合しません。
Markdownは閲覧用、復元はJSONを使用してください。
永続化はブラウザデータの手動削除や端末故障、機種変更を保護しません。

## テスト

Node.jsとPlaywrightのある環境で `node tests/browser.cjs` を実行（テスト内でローカル配信）。
既存記録の移行・照合・再読み込み・過去日時・出力期間名・コピー・削除・復元・別タブの競合・保存失敗・不正な旧データを確認します。
Android実機のホーム画面アイコンとダウンロード確認は利用端末で行ってください。


## クラウド版 v2.0.0

公開先: https://workout-backups.dengana-10011212.workers.dev/

- Notion「アプリのクラウド化」APP-CLOUD-BACKUP v1.0に準拠。今回の指定を優先し、最新3世代を保持。最新データに利用期限なし。
- 記録追加・種目追加/削除・履歴削除・JSON復元の端末保存成功時、同じIndexedDBトランザクションで送信待ちスナップショットを登録。記録ごとに送信し、連続入力を間引かない。
- 通信失敗・オフラインは端末データと送信待ちを保持。接続復帰・再起動・再表示時に再送。アプリを閉じている間の送信は保証しない。
- 同じ操作IDと元の送信端末IDで再送。送信中の追加編集は別更新として保持。保存内容の全取得・照合後だけ古い世代を整理。
- 初回接続時の空データで既存履歴を押し出さない。別端末からの無条件同期なし。本人が選択して履歴から復元。
- 設定内に成功日時、未送信件数、手動保存、履歴復元、端末管理、復元前JSONの書き出しを配置。
- アプリ別256ビット復旧キー、端末別Secure/HttpOnly/SameSite=Strict・ホスト限定Cookie。端末名変更・個別取消・全端末取消・キー変更は復旧キーで再確認。サーバーの通行証に一律の非利用期限なし。
- Worker workout-backupsとD1 personal-apps-sharedを利用。workout_専用テーブル、制約、固有Cookieと認証で他アプリと分離。
- バックアップ上限8MiB。大きいJSONはD1の行サイズ制限内へ分割。秘密・本人の記録は公開成果物へ含めない。APIはno-store、Service Workerのキャッシュ対象外。

### 既存データの移行

1. 今までのPages版で「JSONバックアップを保存」。元の端末データは残す。
2. クラウド版を開き「データ管理・クラウド設定」からJSONを読み込む。
3. 筋トレ専用の復旧キーと端末名で接続。
4. 履歴の件数・種目・日時を確認し、「クラウド保存済み」と成功日時を確認する。
5. 今後はクラウド版を利用。ホーム画面への追加もクラウド版URLから行う。

復元前の端末データと未送信のスナップショットはIndexedDBへ退避。確認中に記録が変更された場合は復元を止める。JSONは従来版と互換で、未知の記録項目と重複IDも保持する。

### ビルド・検証

Node.js 24: npm ci → npx playwright install chromium → npm run build → npm test。
NodeのTypeScript変換を用い、Workerモジュールと公開アセットをcloudflare/distへ生成。配備では全モジュールをアップロードし、D1とDB_TABLE_PREFIX=workout、SecretのBACKUP_TOKEN_SHA256をバインドする。再配備時に既存Secretを保持する。
cloudflare/shared-schema.sqlは初回の筋トレ専用テーブル追加時だけ実行する。他アプリのテーブル変更・削除は含まない。

検証: 旧データの正確な移行、未知の記録項目と重複ID保持、保存失敗・別タブ競合、未認証拒否、別アプリ拒否、CSRF拒否、端末取消とキー変更、3世代保持、同一ID再送、送信中編集、オフライン再起動、復元前退避、空端末保護、CSPとスマホ幅。
